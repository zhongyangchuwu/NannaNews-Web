# NannaNews-Web

南哪消息 PDF 的独立网页阅读器。原刊是内容依据；项目维护活动身份与刊载关系，提供按期阅读、原文查找和本机收藏，不重新采集、补写或校对原稿。

与 [NannaNews](https://github.com/zhongyangchuwu/NannaNews) 后端独立运行，不连接其数据库或摘要库，不需要 Flask、账户、模型密钥或私人云盘。旧后端及旧站的历史资料、验证和分享链接不由本项目修改。

## 本地运行

需要 Node.js 24、Python 3.11+ 和系统 Poppler（`pdftohtml`）。`liteparse==2.14.4` 读取 PDF 语义标签，Poppler 读取原生文字及位置。关闭 OCR，不访问来源网站或调用模型；安装依赖仍需要网络。

```sh
# Ubuntu / WSL；已安装时无需重复执行
sudo apt-get update && sudo apt-get install -y poppler-utils
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
npm ci
npm run import:pdf -- ../NannaNews/pdf
npm run dev
```

输入目录必须显式指定。默认把已接受的数据写入本地私有主文件 `.local-data/catalog.json`，再只读导出到 `.generated/site/data/catalog.json` 供网页读取。后续可以只输入新一期或补入旧 PDF，不必每次提供全部原件。它们不会因未出现在本次输入目录而从主数据中消失。

```sh
npm run import:pdf -- /path/to/new-pdfs
# 从现有主数据重建阅读副本，不解析 PDF、不分配新身份
npm run stage:data -- .local-data/catalog.json
npm run build
npm run preview -- --port 4175
```

若 Python 不在项目 `.venv`，可以用 `PYTHON=/path/to/python` 指定解释器。

## 主数据、原件与派生文件

| 内容 | 位置与责任 |
| --- | --- |
| 已审阅、允许公开的主数据 | `data/catalog.json`，随仓库版本控制；当前为空，没有公开真实资料 |
| 本地开发的私有主数据 | `.local-data/catalog.json`，不提交 Git；不是可随意删除的缓存 |
| PDF 原件 | 显式输入的原刊目录，由持有人保留；只在你允许公开时才提交到 `pdf/` |
| 提取过程材料 | `.cache/pdf/`，可重建，不是成功导入记录，也不是活动身份的来源 |
| 网页阅读副本与构建产物 | `.generated/site/`、`dist/`，从选定主数据生成，不提交 Git |
| 用户收藏 | 当前浏览器的本地存储，不属于公共主数据 |

请备份主数据及其对应原刊。不能只保留缓存，或删除主数据后重新从标题生成身份，再期望旧收藏自然恢复。导入更新使用写入锁和整批校验；失败不会替换旧主文件。备份时先停止导入写入。

重复导入相同 PDF 字节不会创建新刊载、活动或改写已接受事实；原件改名不改变其身份。不同字节却声称属于同一刊期的资料会明确拒绝，不静默覆盖旧刊。第一次接受新资料会从 PDF 实际提取，不把旧缓存中的自报信息直接提升为主数据。

## 数据的含义

主数据使用 `schema_version: 3`，分开保存以下内容：

- **刊物与原刊事实**：`issues`、`listings`、`details`。每行清单及每块正文都有受原件摘要、提取版本和源内标识限定的身份，并保留原刊顺序、原文、栏目、日期字面、链接和页码，不因活动归并而重排或改写。
- **活动身份与刊载关系**：`activities`、`publications`。身份分配后长期保留，刊载关系连接活动和实际来源。一个活动可在多期出现；没有正文也能保留活动及清单。
- **明确的旧身份对应**：`identity_aliases`。只迁移有充分来源证据的旧收藏或链接身份，不把有歧义的旧 ID 强行分配给某个活动。
- **提取提示**：`warnings`。它不是活动状态或原稿校对队列，完整原刊文字仍保留。

活动只有一个逻辑详情入口，其内容引用已收录的原刊正文，不额外维护一套可独立改写的活动介绍。正文尚未收录时详情为空；清单提到过去的刊载日期，不意味着系统已经拥有那期 PDF 或正文。

同名或共用系列网址不等于同一活动。自动关联结合原刊标题、主链接及明确的刊载日期连续性，证据不足或对应不唯一时不强行合并。补入原刊可以建立更完整的来源关系，但不能把旧正文回填成新一期实际印出的内容。原刊正文的不同来源保留各自出处。

清单截止、报名截止和活动发生时间互不替代。标准化日期只是辅助计算；日期原文字面始终保留，无法确定时使用空值而不是延长一年或编造日期。图片内文字不做 OCR；当前网页数据也不是包含全部图片、字体和坐标的完整 PDF 文档树。

## 阅读与收藏

- **本期日报**默认完整读取最新已收录刊物的清单和实际刊印的详解，页头注明真实刊期，不冒充今天的新刊。
- 清单和正文分别按原刊来源顺序展示；同一活动的多行清单不会因归并而丢失或被移动到一起。
- “只看未过清单截止”是可选派生筛选，按北京时间保留截止当天和不确定日期，按活动在本期的最后明确清单截止排序；它不表示报名仍开放。
- **本期新增详解**只列所选刊期实际印有的正文，不用“活动已经有详情”代替“本期刊印正文”。
- 点击清单可打开对应详解。历史正文标明原刊日期，只向同活动的较早刊期查找，不借用未来正文。详解可以返回清单并再次打开。
- **全部期刊**保留按原刊文字检索后选择较新匹配刊载的行为；**我的收藏**可以搜索正在显示的历史说明。
- 勾选即收藏，同一活动在清单和详解中同步，刷新后保留。不增加已读状态，不上传或跨设备同步收藏。当前数据无法对应某个已保存 ID 时保留原记录，不删除或猜测其归属。

### 从旧版目录保留收藏身份

版本 2 的生成目录不是新的原文权威，但可以作为迁移旧收藏 ID 的证据。更新前先在忽略目录中保留它，随后显式迁移：

```sh
mkdir -p .local-data
cp .generated/site/data/catalog.json .local-data/legacy-catalog-v2.json
npm run import:pdf -- /path/to/original-pdfs --legacy-catalog .local-data/legacy-catalog-v2.json
```

这段复制仅用于仍持有 **版本 2** 目录的首次切换，不要把版本 3 主文件当成旧目录。迁移要核对原件摘要和实际源内容，不使用旧条目顺序来恢复原刊顺序。能够唯一确认的旧 ID 成为别名；无法唯一恢复的裸 ID 会继续保存在浏览器中，不会被反向猜测、删除或扇出到多个活动。旧版运行时目录不与新脚本混用。

## 手动审阅与只读发布

**当前流程不自动提交主数据，不新增仓库写权限。** 本地工具产生候选变更，PR 审查与合并是接受边界，Actions 只读取已提交的主数据校验、打包与部署。

只有在你已明确允许公开时，才对公共主文件导入：

```sh
npm run import:pdf -- /path/to/approved-public-pdfs --catalog data/catalog.json
```

不要把包含私有资料的 `.local-data/catalog.json` 直接复制进公开仓库。公共主数据应只包含获准公开的内容及来源关系。原始 PDF 是否公开是另一项决定；网站不会自动复制原件或解析证据。

1. 在新分支中提交公共主数据变更。若也提交原 PDF，只放入 `pdf/`。
2. 审阅新增原文、来源顺序、活动归属和身份变化；不能把重新分配全部 ID 当成普通内容更新。原文对应与活动归属的语义判断仍需审阅，不由结构校验代替。
3. Actions 校验版本化主数据的结构及引用关系；已提交 PDF 的摘要必须出现在主数据中，不能只上传原件却未登记来源。
4. Actions 使用独立 checkout，只读导出 `data/catalog.json` 并构建网站，不运行 PDF 导入器，也不写回 Git。合并到主分支后才部署。

Pages 的 Source 使用 **GitHub Actions**。空的公共主数据会使内容构建和发布跳过；代码检查中的合成样例不会启用发布，也没有产物上传。

只上传 PDF 而让机器人补全主数据、提交候选变更，属于以后的自动化步骤，当前未启用。私有主数据、缓存、构建目录和近期原刊都不能用 `git add -f` 绕过边界。

公开仓库中的资料会留在可下载的 Git 历史中；站点 JSON 中的原文也可被公开读取，不是隐藏的私有数据库。不要迁入旧后端数据库、工作簿、付费回执、私人附件或凭据。

```sh
npm test
.venv/bin/python -m pytest -q
npm run check
node scripts/check-input-boundary.mjs
node --experimental-strip-types scripts/published-inputs.mjs
```

永久测试只用合成数据。实际原刊的增量导入、重复导入、补刊、旧身份迁移、正文和清单顺序及手机阅读需要另做本地验收，不能由测试通过代替。

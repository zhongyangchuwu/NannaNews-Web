# NannaNews-Web

南哪消息的独立静态阅读器。PDF 原刊按日期读日报、按活动查资料，另保留获准公开的旧版历史整理资料；两者区分来源，共用本机收藏，不重新采集、补写或校对原稿。

与 [NannaNews](https://github.com/zhongyangchuwu/NannaNews) 后端独立运行，不连接其数据库或摘要库，不需要 Flask、账户、模型密钥或私人云盘。历史资料从固定的公开快照迁入，不改动旧后端、旧站及其分享链接。

## 本地运行

需要 Node.js 24、Python 3.11+ 和系统 Poppler（`pdftohtml`）。`liteparse==2.14.4` 读取 PDF 语义标签，Poppler 读取原生文字及位置。关闭 OCR，不访问来源网站或调用模型；安装依赖仍需要网络。

```sh
# Ubuntu / WSL；已安装时无需重复执行
sudo apt-get update && sudo apt-get install -y poppler-utils
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
npm ci
npm run import:pdf -- ../NannaNews/pdf
npm run dev
```

输入目录必须显式指定。默认把已接受的数据写入本地私有主文件 `.local-data/catalog.json`，再只读导出到 `.generated/site/data/catalog.json` 供网页读取。后续可以只输入新一期或补入旧 PDF，不必每次提供全部原件。它们不会因未出现在本次输入目录而从主数据中消失。

```sh
npm run import:pdf -- /path/to/new-pdfs
# 从现有主数据重建阅读副本，不解析 PDF、不分配新身份
npm run stage:data -- .local-data/catalog.json
# 首次准备完整历史档案：下载约 866 MB 的固定公开资源包并校验
npm run stage:history
npm run build
npm run preview -- --port 4175
```

若 Python 不在项目 `.venv`，可以用 `PYTHON=/path/to/python` 指定解释器。

只阅读仓库中已审阅的公开资料时，用 `npm run stage:data -- data/catalog.json` 代替导入或私有主文件导出，再运行 `npm run stage:history`。开发服务器可只读当前已暂存的资料；正式 `build` 要求完整历史资源和原件清单齐备，缺失、损坏或超出 Pages 1 GB 上限会拒绝构建，不降级为只有摘要的网页。

## 主数据、原件与派生文件

| 内容 | 位置与责任 |
| --- | --- |
| 已审阅、允许公开的主数据 | `data/catalog.json`，随仓库版本控制，独立于本地私有主数据 |
| 本地开发的私有主数据 | `.local-data/catalog.json`，不提交 Git；不是可随意删除的缓存 |
| PDF 原件 | 显式输入的原刊目录，由持有人保留；只在你允许公开时才提交到 `pdf/` |
| 历史快照配置与资源包 | `data/history.json` 固定公开 Release 地址、版本、大小和 SHA-256；缓存 `.cache/history/`，只读暂存到 `.generated/site/history-data/` |
| 历史原件及来源清单 | `history/originals/<sha256>.html` 或 `.pdf`，与 `pdf/` 按字节摘要去重；`data/history-originals.json` 保留别名、登记日期及固定的原件提交 |
| 提取过程材料 | `.cache/pdf/`，可重建，不是成功导入记录，也不是活动身份的来源 |
| 网页阅读副本与构建产物 | `.generated/site/`、`dist/`，从选定主数据生成，不提交 Git |
| 用户收藏 | 当前浏览器的本地存储，不属于公共主数据 |

请备份主数据及其对应原刊。不能只保留缓存，或删除主数据后重新从标题生成身份，再期望旧收藏自然恢复。导入更新使用写入锁和整批校验；失败不会替换旧主文件。备份时先停止导入写入。

这里的“私有主数据”指尚未发布的本地主数据，不是浏览器收藏，也不意味着其中每条内容都属秘密。不要用它整体覆盖已审阅的公共主数据。

重复导入相同 PDF 字节不会创建新刊载、活动或改写已接受事实；原件改名不改变其身份。不同字节却声称属于同一刊期的资料会明确拒绝，不静默覆盖旧刊。第一次接受新资料会从 PDF 实际提取，不把旧缓存中的自报信息直接提升为主数据。

## 数据的含义

主数据使用 `schema_version: 3`，分开保存以下内容：

- **刊物与原刊事实**：`issues`、`listings`、`details`。每行清单及每块正文都有受原件摘要、提取版本和源内标识限定的身份，并保留原刊顺序、原文、栏目、日期字面、链接和页码，不因活动归并而重排或改写。
- **活动身份与刊载关系**：`activities`、`publications`。身份分配后长期保留，刊载关系连接活动和实际来源。一个活动可在多期出现；没有正文也能保留活动及清单。
- **明确的旧身份对应**：`identity_aliases`。只迁移有充分来源证据的旧收藏或链接身份，不把有歧义的旧 ID 强行分配给某个活动。
- **提取提示**：`warnings`。它不是活动状态或原稿校对队列，完整原刊文字仍保留。

活动只有一个逻辑详情入口，其内容引用已收录的原刊正文，不额外维护一套可独立改写的活动介绍。正文尚未收录时详情为空；清单提到过去的刊载日期，不意味着系统已经拥有那期 PDF 或正文。

同名或共用系列网址不等于同一活动。自动关联结合原刊标题、主链接及明确的刊载日期连续性，证据不足或对应不唯一时不强行合并。补入原刊可以建立更完整的来源关系，但不能把旧正文回填成新一期实际印出的内容。原刊正文的不同来源保留各自出处。

清单截止、报名截止和活动发生时间互不替代。标准化日期只是辅助计算；日期原文字面始终保留，无法确定时使用空值而不是延长一年或编造日期。图片内文字不做 OCR；当前网页数据也不是包含全部图片、字体和坐标的完整 PDF 文档树。

## 阅读与收藏

- **日报**默认跟随北京时间今天，不自动跳到最新已收录刊物。选择日期后固定阅读那一天，刷新或跨午夜不切换；点击“回到今天”恢复跟随。日期指原刊刊期，不是活动发生日期。
- 日期导航使用周一至周日的月历，可直接选择月份、输入年份或前后翻月，点击日期跳转；切换日期保留原阅读视图和筛选。月历区分有新增、已收录但无新增说明、尚未收录，数量不随筛选变化。未收录不代表当天没有消息或停刊；资料读取失败单独报错并可重试。
- **新增消息**是默认的独立视图，只列当天实际刊印的正文，不把历史说明算作新增。**原刊清单**是另一视图，默认保留全部清单行。两者各按原刊来源顺序展示，同一活动的多行清单不会因归并而丢失；同日多期按期号、源内顺序阅读。日期导航中的收录数量不随关键词或栏目筛选变化。
- 日报的“只看未过清单截止”是可选派生筛选，按北京时间保留截止当天和不确定日期，按活动在当前刊载中的最后明确清单截止排序；它不表示报名仍开放。
- 点击清单可打开本期说明，或注明真实刊期的较早说明，不借用未来正文。返回时保留原来的日期、清单行和筛选。旧版刊期、正文及已确认身份链接继续对应实际来源；无法对应的刊期不会被替换成最新一期。
- **当前活动**只列最近一份有清单的刊载中截止明确、且按北京时间尚未过期的活动，截止当天仍保留，按截止日期从近到远排列。截止未知或仅有正文的活动不列在本页，但仍可在“所有活动”查找；不改写原刊日期或推断报名状态。
- **所有活动**聚合已接受 PDF 原刊中的稳定活动身份，同一活动只列一次，按最近真实刊载排序。搜索覆盖这些原刊的所有已收录标题和正文，并注明匹配来源；活动详情引用最近一份实际刊印的正文，附完整刊载历史。尚未收录正文时明确说明，不补写内容。可筛选全部、明确未过截止、已过截止或截止未知，筛选在活动与来源之间返回时保留。更早的整理资料从“历史档案”进入，不按同名标题与本页强行归并。
- 清单截止、刊载日期和来源链接显示完整年份。无法确定的日期保留原文字面或显示“未明确”，不猜测年份；正文中的原始日期不改写。
- 点击“收藏”后显示“已收藏”，再次点击取消。同一活动在清单、正文及收藏页中同步，刷新后保留。不增加已读状态，不上传或跨设备同步收藏。当前数据无法对应某个已保存 ID 时保留原记录，不删除或猜测其归属。
- **历史档案**保留旧版 7,140 个活动、27,487 条刊载记录、510 期刊物的身份、别名、完整整理正文、日期依据、来源状态和 3,103 张已留存图片。目录按 20 个活动分页，首页通过紧凑索引只读取当前页对应的刊期，不先下载整份活动目录；搜索及年月筛选使用独立索引，正文和图片按需加载。刊期、原件列表与正文分别加载，原件清单失败不阻塞正文。页面只保留操作、状态和来源事实，不重复展示本节的筛选规则。`verified` 不等于人工核实，历史整理或推定日期也不冒充 PDF 原文或当前报名状态。
- **全部原件**可检索 673 份历史 HTML/PDF 的文件名、别名、登记日期和摘要，并按 SHA 与新增 PDF 原件合并展示。刊期关系只取明确的文件摘要关联，不把重复文件的日期别名编造成多期日报。HTML 只在 GitHub 查看源码或获取原件，绝不嵌入网页执行；历史原件链接固定到保存字节的提交，新增日报 PDF 链接到只追加、不覆盖文件的 `main/pdf/`。
- **我的收藏**分别展示 PDF 活动与历史档案收藏，沿用本页的原刊筛选和档案的搜索、年月筛选，详情返回保留来源条件。不读取旧站另一套浏览器偏好，也不为没有历史收藏的用户加载整份历史目录。

### 从旧版目录保留收藏身份

版本 2 的生成目录不是新的原文权威，但可以作为迁移旧收藏 ID 的证据。更新前先在忽略目录中保留它，随后显式迁移：

```sh
mkdir -p .local-data
cp .generated/site/data/catalog.json .local-data/legacy-catalog-v2.json
npm run import:pdf -- /path/to/original-pdfs --legacy-catalog .local-data/legacy-catalog-v2.json
```

这段复制仅用于仍持有 **版本 2** 目录的首次切换，不要把版本 3 主文件当成旧目录。迁移要核对原件摘要和实际源内容，不使用旧条目顺序来恢复原刊顺序。能够唯一确认的旧 ID 成为别名；无法唯一恢复的裸 ID 会继续保存在浏览器中，不会被反向猜测、删除或扇出到多个活动。旧版运行时目录不与新脚本混用。

## GitHub 网页上传与审阅发布

上传者需要仓库 **Write 或管理员权限**；维护者在仓库 Settings → Collaborators 中授予合适的人员写权限。只读账号、Fork PR 和 Issue 附件不进入自动导入流程。不需要另一套登录系统或模型密钥。

**公开仓库不是私有上传箱。** 上传到分支的 PDF 已可被公开下载，提取全文也会进入 PR 和 Git 历史；合并只是网页接受边界，不是保密边界。上传前必须确认原件及全文均获准公开。

1. 在 GitHub 打开 [`pdf/`](pdf/)，选择 **Add file → Upload files**，拖入一批新 PDF。只放在本目录，不放子目录，不覆盖已有原件。
2. 提交时选择 **新建分支并创建 Pull Request**，目标为当前 `main`，不要直接提交主分支，也不要建立草稿 PR。这次上传 PR 只包含新增 PDF，不混入代码或手改 `data/catalog.json`。
3. Actions 核对作者、事件操作者及重跑操作者的当前写权限，使用主分支的可信代码解析，并在同一 PR 中提交生成的 `data/catalog.json`。不执行上传分支的程序；解析和独立校验没有仓库写权限，最后的写入任务只提交已验证的目录文件，不向 `main` 推送。
4. 查看 **Files changed**，核对新增原文、来源顺序、活动归属和身份变化。结构校验不代替原文及归属审阅，不能把重新分配全部 ID 当成普通更新。
5. 确认 **PDF upload candidate** 和仓库要求的其他检查通过。机器人提交后，GitHub 可能要求有写权限的人批准普通 PR 工作流运行；候选检查不会冒充这些检查。初次只有 PDF 的提交可能因尚未登记主数据而检查失败，应查看机器人写回后的最新提交。
6. 人工审阅、合并到 `main` 后，现有 Pages 流程自动校验、只读导出主数据并发布网页。机器人不批准或合并 PR；上传前、未合并 PR 或开发验证产物不会部署到 Pages。

机器人写回了变更后的主数据后，这个 PR 的批次就固定了；不要继续追加 PDF 或手工覆盖目录，请从当前主分支另开上传 PR。相同字节的重复原件不会重建身份；若目录完全不变，不创建空提交，候选检查直接关联原提交，这类 PR 仍可继续添加新 PDF。分支必须包含当前主分支；基础版本或头提交变化会停止旧候选写入，不能用强制推送绕过。

若目录提交成功但创建候选检查失败，先检查 PR 的最新提交，批准或运行普通校验并人工核对；不要删除目录来反复重建身份。首次运行自动化需要先把实现工作流合并到默认分支。

维护者预合并验证：在 **Actions → Check and publish PDF reader → Run workflow** 选择已审阅的实现分支，填写以该分支为目标的上传 PR 号 `upload_pr`。这会运行同一导入、独立校验和写回流程，仅允许非默认分支，不发布 Pages；不要选择未经审阅的上传代码分支。正常上传不需要这一步。

本地开发继续使用私有主数据。只有已获准公开的资料才可显式导入公共目录：

```sh
npm run import:pdf -- /path/to/approved-public-pdfs --catalog data/catalog.json
```

不要把 `.local-data/catalog.json` 整体复制进公开仓库，也不要提交解析证据、缓存、数据库、工作簿、付费回执、私人附件或凭据。私有目录和构建产物不能用 `git add -f` 绕过边界。

Pages 的 Source 使用 **GitHub Actions**。空的公共主数据使内容构建和发布跳过；代码检查中的合成样例不启用发布，也不上传发布产物。

内容构建从已审阅主数据和已校验的公开历史包生成。原始 HTML、数据库、运行配置和提取证据不进入静态站点；历史 JSON 保持 gzip 存储以控制体积，浏览器同时支持原始 gzip 响应与服务器通过 HTTP 自动解压的响应。原件清单校验要求其 `source_ref` 指向的真实提交保留在 Git 历史中：合并历史迁移时保留原件提交，不用 squash 或重写该提交；CI 取完整历史核对文件字节。

# NannaNews-Web

南哪消息 PDF 的独立网页阅读器。已有 PDF 是内容依据：整理清单、查找往期、收藏和打开原始通知，不重新采集、补写活动信息或调用模型。

与 [NannaNews](https://github.com/zhongyangchuwu/NannaNews) 后端独立运行；不需要 Flask、数据库、后端账户、模型密钥或私人云盘。旧后端及旧站的历史资料、验证和分享链接不由本项目修改。

## 本地运行

需要 Node.js 24、Python 3.11+ 和系统 Poppler（`pdftohtml`）。`liteparse==2.14.4` 随 Python 工具安装：LiteParse 读取语义标签，Poppler 保留原始文字、位置和链接。解析关闭 OCR，不访问来源网站或调用模型；安装软件依赖仍需要网络。

```sh
# Ubuntu / WSL 安装系统文字读取器；已安装时无需重复执行
sudo apt-get update && sudo apt-get install -y poppler-utils
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
npm ci
npm run import:pdf -- ../NannaNews/pdf
npm run dev
```

`import:pdf` 必须显式指定输入目录。可以直接读取仓库外已有的 `../NannaNews/pdf`，不需要复制或提交原件。若本机 Python 环境不在 `.venv`，可用 `PYTHON=/path/to/python` 指定解释器。

- `.generated/site/data/catalog.json`：本地生成的网页目录。
- `.cache/pdf/`：本地解析依据与缓存，可能包含原始 PDF，绝不公开。
- `dist/`：本地构建结果，不提交 Git。
- `local-pdf/`：可选的、已忽略的本地开发输入目录。
- `pdf/`：只用于你已明确决定公开并提交的 PDF。当前近期 PDF 不需要、也不应搬进这里。

生成数据、缓存、构建目录和本地 PDF 都不随源码上传。不要使用 `git add -f` 绕过忽略规则。普通构建不复制 PDF 原件或解析依据到网页。

```sh
npm run build
npm run preview -- --port 4175
```

没有有效的生成目录时，构建会明确失败，不使用虚构消息填充页面。开发服务器的数据缺失或读取失败也提供明确提示和重试。

## 原刊来源结构

网页只读取离线生成的 JSON，不连接旧后端数据库，也不在浏览器中重新解析 PDF。

生成目录使用 `schema_version: 2`。同一消息可以同时保留两种原刊来源：

- `listings`：每一行原始清单，包含短标题、清单截止、刊载日期、原文字面、标题链接和页码。多行不会只剩一个最大日期。
- `detail`：本期 PDF 中实际刊印的说明，包含完整标题、正文、原刊标注字段、原文链接、其他链接和页码；本期没有详解时为 `null`。

“本期新增说明”按本期是否印有正文判定，不推断活动在现实中是否首次出现。页面按原刊分为紧凑的“原刊清单”和完整的“本期新增详解”，同一活动可以同时出现在两处。勾选即收藏，两处状态同步，不另外生成一份活动或改写正文。

时间、地点等要点保留原刊标签，不把“工作时间”“拍曲时间”统一改称活动日期。无法确定的字段边界会报告警告并保留完整正文，不输出看似精确的残缺值。原文主链接和报名、投递等其他链接分开，完整 URI（包括查询参数和片段）不从打印网址猜测或拼接。

解析针对已有 Typst 标签和清单模板。文字无法归属、链接归属有歧义、未支持的复合列表或嵌套表格、超出资源限量时，导入明确失败并保留上次目录，不发布部分结果。图片内的文字不做 OCR。

旧版生成目录不与新版脚本混用；更新后重新执行 `import:pdf` 和 `build`。新版解析缓存与旧版隔离，不复用已丢失字形或错序的结果。

## 阅读规则

- **本期日报**默认展示最新一期 PDF 的完整清单和本期说明，保留栏目及原始清单行。页头注明真实刊期，不把旧刊冒充今天的新刊。“只看未过清单截止”是可选筛选，按北京时间保留截止当天及未明确日期的条目，明确截止最近的优先。
- **清单截止、报名截止、实际活动时间互不替代**。清单截止不代表此刻仍可报名；报名细则查看原文。
- 日期未明确的清单行保留原文字面，不被当成长期有效活动；没有清单行的说明仍在详解区展示。
- **往期日报**按期保留原有信息与过期条目；“全部期刊”可跨期搜索，并按稳定消息身份去重。
- **我的收藏**沿用本浏览器的收藏记录，清单和详解中的方框均可勾选、取消，刷新后保留；不能跨设备同步。当前数据缺少某条已收藏消息时保留其收藏记录，不自动删除。
- 清单标题与完整正文标题分别保留，包括原刊写明的学院等限定信息；原文 URI 只使用已有链接，不猜测地址。不把刊物回溯地址充作活动原文。
- 清单与正文在同刊、分类相容且标题或原文唯一对应时关联；共享网址的多场讲座仍分开。不确定的关联不强行建立，双方原刊内容都保留。无法确认的日期保留原文字面并报告，不被其他明确日期遮盖。
- 清单点击标题可定位本期详解；本期没有正文时，按同一稳定身份查找最近的已收录往期说明，链接注明原刊日期并切换到对应刊期。历史说明不算本期新增，不借用未来刊期的正文，也不回填或覆盖当前清单截止。详解内可一键回到清单。

PDF 表格省略年份时，以正文明确的刊期年为上下文；只有明确跨年方向的月份关系才切换年份，最近已过的截止不会延长一年。正文无法确认的年份、区间或列表不自动当成一个确定日期。

## 检查

```sh
npm test
.venv/bin/python -m pytest -q
npm run check
node scripts/check-input-boundary.mjs
```

永久测试使用合成数据，不提交近期 PDF、生成目录或解析快照。实际 PDF 的版式、清单行数、截止、链接和手机阅读需要在本地另行对照，不能用测试通过代替内容验收。

## GitHub 上传与发布

未来选定允许公开的 PDF 后，可通过仓库网页的 **Add file → Upload files** 上传到 `pdf/` 的新分支，创建 PR：

1. Actions 自动检查代码，并在有已提交 PDF 时离线解析、校验、构建内容。
2. 阅读 Actions 的提取摘要，确认日期、条目和异常后合并。
3. 主分支仅在存在已提交 PDF 时生成真实内容产物并部署 GitHub Pages。

仓库设置中将 Pages 的 Source 选择为 **GitHub Actions**。没有已提交 PDF 时，内容构建和发布会跳过；不会把合成测试数据或空页面上线。

代码检查用合成目录验证打包，但不上传任何产物。真实内容作业使用独立 checkout，只处理已提交的 `pdf/`；发布目录只允许经过校验的目录 JSON 和前端资源。解析或校验失败时不执行部署，保留先前站点。JSON 与网页不自动回写 Git，不需要个人访问令牌、模型密钥或后端权限。

公开仓库中的 PDF 会成为可下载的 Git 历史；网站 JSON 中的标题、正文等也能被公开读取，不是私有数据库。只上传你允许公开分发的资料，不迁入旧后端的数据库、来源快照、付费回执、私人附件或凭据。
